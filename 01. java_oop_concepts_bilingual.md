# Java OOP (Object-Oriented Programming) Concepts
*(Các khái niệm Lập trình Hướng đối tượng trong Java)*

**Last Updated:** 23 Oct, 2026 *(Cập nhật lần cuối: 23/10/2026)*

**Object-Oriented Programming (OOP)** is a programming paradigm based on the concept of objects that contain data (fields) and behavior (methods). It focuses on designing software that closely represents real-world entities. It is used to:
*(**Lập trình hướng đối tượng (OOP)** là một mô hình lập trình dựa trên khái niệm về các đối tượng chứa dữ liệu (thuộc tính/fields) và hành vi (phương thức/methods). Nó tập trung vào việc thiết kế phần mềm mô phỏng sát với các thực thể trong thế giới thực, giúp:)*

* **Improves code reusability** *(Cải thiện khả năng tái sử dụng mã nguồn)*
* **Enhances maintainability and scalability** *(Nâng cao khả năng bảo trì và mở rộng)*
* **Makes programs easier to understand and manage** *(Giúp chương trình dễ hiểu và dễ quản lý hơn)*

## Characteristics of OOP *(Các đặc điểm / Khái niệm cốt lõi của OOP)*

### 1. Class *(Lớp)*
A **Class** in Java is a blueprint or template used to create objects. It defines the properties (data) and behaviors (methods) that objects of that class will have.
*(**Lớp** trong Java là một bản thiết kế hoặc khuôn mẫu dùng để tạo ra các đối tượng. Nó định nghĩa các thuộc tính (dữ liệu) và hành vi (phương thức) mà các đối tượng thuộc lớp đó sẽ có.)*

* A class is a user-defined data type. *(Lớp là một kiểu dữ liệu do người dùng tự định nghĩa.)*
* It contains variables (fields) and methods. *(Nó chứa các biến thành viên và các phương thức.)*
* Multiple objects can be created from a single class. *(Có thể tạo ra nhiều đối tượng từ một lớp duy nhất.)*

> **Example:** A `Car` represents a class (blueprint), while `BMW`, `Mercedes`, and `Audi` represent objects (instances) created from that class.
> *(**Ví dụ:** `Car` đại diện cho một lớp (bản thiết kế), trong khi `BMW`, `Mercedes` và `Audi` đại diện cho các đối tượng (thể hiện) được tạo ra từ lớp đó.)*

---

### 2. Object *(Đối tượng)*
An **Object** in Java is an instance of a class that represents a real-world entity. It is used to access the variables and methods defined inside a class.
*(**Đối tượng** trong Java là một thể hiện cụ thể của một lớp, đại diện cho một thực thể ngoài đời thực. Nó được dùng để truy cập các biến và phương thức đã định nghĩa bên trong lớp.)*

* **State *(Trạng thái)*:** Represents the current data or attributes of an object. *(Đại diện cho dữ liệu hoặc thuộc tính hiện tại của đối tượng.)*
* **Behavior *(Hành vi)*:** Represents the actions that an object can perform. *(Đại diện cho các hành động mà đối tượng có thể thực hiện.)*
* **Identity *(Danh tính)*:** Every object has a unique identity in memory that distinguishes it from other objects, even if they contain the same data. *(Mỗi đối tượng có một định danh duy nhất trong bộ nhớ để phân biệt với các đối tượng khác, ngay cả khi chúng chứa dữ liệu giống hệt nhau.)*

> **Example:** `Dog` is a class, `Tommy` is an object of that class.
> *(**Ví dụ:** `Dog` là một lớp, và `Tommy` là một đối tượng thuộc lớp đó.)*

```java
class Dog {
    String name; // State (Trạng thái)

    void bark() { // Behavior (Hành vi)
        System.out.println(name + " is barking!");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog tommy = new Dog(); // Object (Đối tượng)
        tommy.name = "Tommy";
        tommy.bark();
    }
}
```

### 3. Constructor *(Hàm khởi tạo)*
A **Constructor** is a special member of a class that is automatically invoked when an object is created. It is primarily used to initialize the object's data members and set up the initial state of an object.
*(**Hàm khởi tạo (Constructor)** là một thành phần đặc biệt của lớp, được tự động gọi khi một đối tượng được tạo ra. Mục đích chính của nó là khởi tạo giá trị cho các thuộc tính và thiết lập trạng thái ban đầu cho đối tượng.)*

* Constructor name must be the same as the class name. *(Tên constructor phải trùng khớp hoàn toàn với tên lớp.)*
* It does not have any return type, not even `void`. *(Không có bất kỳ kiểu trả về nào, kể cả `void`.)*
* It is automatically called when an object is created using the `new` keyword. *(Tự động được gọi khi tạo đối tượng bằng từ khóa `new`.)*
* Constructors help initialize object properties during object creation. *(Giúp khởi tạo các thuộc tính ngay trong lúc tạo đối tượng.)*

> **Example:** When creating a `Car` object, a constructor can automatically assign values such as `brand`, `model`, and `color`.
> *(**Ví dụ:** Khi tạo một đối tượng `Car`, constructor có thể tự động gán các giá trị như hãng xe, dòng xe và màu sắc.)*

#### Types of Constructor *(Các loại Constructor)*:
* **Default Constructor *(Constructor mặc định)*:** A constructor that does not accept any parameters and initializes an object with default values. *(Không nhận tham số nào và khởi tạo đối tượng với các giá trị mặc định.)*
* **Parameterized Constructor *(Constructor có tham số)*:** A constructor that accepts parameters to initialize an object with specific values. *(Nhận các tham số truyền vào để khởi tạo đối tượng với các giá trị cụ thể.)*
* **Copy Constructor *(Constructor sao chép)*:** A user-defined constructor that creates a new object by copying the data of another object of the same class. *(Constructor do người dùng định nghĩa để tạo một đối tượng mới bằng cách sao chép dữ liệu từ một đối tượng khác cùng lớp.)*
* **Private Constructor *(Constructor riêng tư)*:** A constructor declared with the `private` access modifier that prevents object creation from outside the class. *(Được khai báo với từ khóa `private` nhằm ngăn chặn việc khởi tạo đối tượng từ bên ngoài lớp — thường dùng trong Singleton Pattern.)*

### 4. Abstraction *(Tính trừu tượng)*
**Abstraction** in Java is the process of hiding implementation details and showing only the essential features of an object. It helps users focus on what an object does rather than how it does it.
*(**Tính trừu tượng** trong Java là quá trình ẩn đi các chi tiết cài đặt phức tạp và chỉ hiển thị những tính năng cốt lõi nhất của đối tượng. Nó giúp người dùng tập trung vào việc đối tượng **làm gì** thay vì **làm như thế nào**.)*

* **Hides complexity *(Ẩn sự phức tạp)*:** Internal implementation details are hidden from the user. *(Các chi tiết xử lý bên trong được giấu kín khỏi người dùng.)*
* **Improves maintainability *(Cải thiện bảo trì)*:** Changes in implementation do not affect the user code. *(Thay đổi cách cài đặt bên trong không làm ảnh hưởng đến code của người dùng bên ngoài.)*
* **Enhances flexibility *(Tăng tính linh hoạt)*:** Supports loose coupling through abstract classes and interfaces. *(Hỗ trợ giảm sự phụ thuộc chặt chẽ (loose coupling) thông qua lớp trừu tượng và giao diện.)*

> **Example:** An ATM or a coffee machine represents abstraction, where the user interacts with simple operations while the internal working and implementation details remain hidden.
> *(**Ví dụ:** Máy ATM hoặc máy pha cà phê đại diện cho tính trừu tượng, nơi người dùng chỉ thao tác với các nút bấm đơn giản trong khi cơ chế hoạt động bên trong được ẩn đi.)*

#### How to Achieve Abstraction *(Cách đạt được Tính trừu tượng)*:
* It is achieved in Java using **abstract classes** and **interfaces**. *(Trong Java, tính trừu tượng đạt được thông qua `abstract class` và `interface`.)*
* Interfaces can provide **100% abstraction**, while abstract classes provide **partial abstraction**. *(Interface có thể cung cấp tính trừu tượng 100%, trong khi abstract class cung cấp tính trừu tượng một phần.)*

> **Example:** Abstract class defines a common base (`Shape`) using inheritance, while an interface (`Drawable`) defines behavior implemented by multiple classes.
> *(**Ví dụ:** Lớp trừu tượng định nghĩa nền tảng chung (`Shape`) thông qua kế thừa, trong khi giao diện (`Drawable`) định nghĩa hành vi để nhiều lớp khác nhau triển khai.)*

### 5. Encapsulation *(Tính đóng gói)*
**Encapsulation** is the process of wrapping data and methods into a single unit, usually a class, and restricting direct access to the data. It acts as a protective shield that prevents data from being accessed directly from outside the class.
*(**Tính đóng gói** là quá trình gói gọn dữ liệu và các phương thức vào chung một đơn vị duy nhất (thường là một class), đồng thời hạn chế quyền truy cập trực tiếp vào dữ liệu đó. Nó đóng vai trò như một lớp khiên bảo vệ ngăn dữ liệu bị truy xuất tự do từ bên ngoài.)*

* Data members are hidden using the `private` access modifier. *(Các biến dữ liệu được ẩn đi bằng từ khóa truy cập `private`.)*
* Access to data is provided through `public` getter and setter methods. *(Việc đọc và sửa dữ liệu được cung cấp thông qua các phương thức `getter` và `setter` công khai.)*
* It improves data security, maintainability, and controlled access. *(Nâng cao tính bảo mật dữ liệu, dễ bảo trì và kiểm soát quyền truy cập chặt chẽ.)*

```java
class Account {
    private double balance; // Dữ liệu được bảo vệ bằng private

    public void setBalance(double balance) {
        if (balance >= 0) this.balance = balance;
    }

    public double getBalance() {
        return balance;
    }
}
```

### 6. Association *(Mối quan hệ liên kết)*
**Association** is an OOP concept that defines a relationship between two or more classes that are connected to each other. It represents how objects interact with each other and communicate. In association, objects of one class are related to objects of another class, but they can exist independently.
*(**Association (Liên kết)** là khái niệm OOP định nghĩa mối quan hệ giữa hai hay nhiều lớp kết nối với nhau. Nó thể hiện cách các đối tượng tương tác và giao tiếp với nhau, trong đó các đối tượng có liên quan nhưng vẫn có thể tồn tại độc lập.)*

* Represents a relationship between objects. *(Thể hiện mối quan hệ giữa các đối tượng.)*
* Does not imply ownership. *(Không hàm ý sự sở hữu bắt buộc.)*
* Objects are independent of each other. *(Các đối tượng độc lập với nhau.)*

#### Types of Association *(Các loại liên kết)*:

1. **Aggregation (Weak Association) *(Kết tập - Liên kết yếu)*:**
   Aggregation represents a **"has-a"** relationship where one class contains a reference to another class, but both can exist independently.
   *(Thể hiện mối quan hệ **"có một" (has-a)**, nơi một lớp chứa tham chiếu đến lớp khác, nhưng cả hai đều có thể tồn tại độc lập.)*
   * It is a weak relationship. *(Là mối quan hệ yếu.)*
   * Objects have independent lifecycles. *(Các đối tượng có vòng đời độc lập.)*
   * One object can exist without the other. *(Đối tượng này vẫn tồn tại được nếu đối tượng kia mất đi.)*
   * **Example:** A `Company` has `Employees`, but employees can exist independently even if the company no longer exists. *(Một Công ty có các Nhân viên, nhưng nhân viên vẫn tồn tại độc lập ngay cả khi công ty giải thể.)*

2. **Composition (Strong Association) *(Hợp thành - Liên kết mạnh)*:**
   Composition is a strong form of association where one class owns another class. If the parent object is destroyed, the child object also gets destroyed.
   *(Là dạng liên kết chặt chẽ, nơi một lớp sở hữu hoàn toàn lớp kia. Nếu đối tượng cha bị hủy, đối tượng con cũng bị hủy theo.)*
   * It is a strong relationship. *(Là mối quan hệ mạnh.)*
   * Objects have dependent lifecycles. *(Các đối tượng có vòng đời phụ thuộc lẫn nhau.)*
   * Child object cannot exist without the parent. *(Đối tượng con không thể tồn tại nếu thiếu đối tượng cha.)*
   * **Example:** A `House` is composed of `Rooms`, and if the house is destroyed, the rooms cannot exist independently. *(Một Ngôi nhà được cấu thành từ các Căn phòng; nếu ngôi nhà bị phá hủy, các căn phòng không thể tồn tại độc lập.)*

### 7. Inheritance *(Tính kế thừa)*
**Inheritance** is a core OOP concept in Java that allows one class to acquire the fields and methods of another class using the `extends` keyword. It represents an **"is-a"** relationship between classes.
*(**Tính kế thừa** là khái niệm cốt lõi trong Java cho phép một lớp thừa hưởng các thuộc tính và phương thức của một lớp khác thông qua từ khóa `extends`. Nó đại diện cho mối quan hệ **"là một" (is-a)** giữa các lớp.)*

* The class being inherited is called the **superclass**, and the inheriting class is the **subclass**. *(Lớp được kế thừa gọi là **lớp cha (superclass)**, và lớp đi kế thừa gọi là **lớp con (subclass)**.)*
* A subclass can use existing features of the superclass and also add its own. *(Lớp con có thể sử dụng các tính năng có sẵn của lớp cha và bổ sung thêm tính năng riêng.)*
* Inheritance promotes code reusability and reduces redundancy. *(Thúc đẩy tái sử dụng mã nguồn và giảm sự dư thừa/lặp code.)*

> **Example:** `Dog`, `Cat`, `Cow` can be Derived Classes of `Animal` Base Class.
> *(**Ví dụ:** `Dog`, `Cat`, `Cow` có thể là các lớp dẫn xuất (lớp con) kế thừa từ lớp cơ sở `Animal`.)*

#### Types of Inheritance *(Các loại kế thừa trong Java)*:
* **Single Inheritance *(Đơn kế thừa)*:** One subclass inherits from one superclass. *(Một lớp con kế thừa từ một lớp cha.)*
* **Multilevel Inheritance *(Kế thừa nhiều cấp)*:** A class is derived from another derived class, forming a chain. *(Một lớp kế thừa từ một lớp con khác, tạo thành chuỗi phân cấp: Ông $\rightarrow$ Cha $\rightarrow$ Con.)*
* **Hierarchical Inheritance *(Kế thừa thứ bậc)*:** Multiple subclasses inherit from a single superclass. *(Nhiều lớp con cùng kế thừa từ một lớp cha duy nhất.)*
* **Multiple Inheritance (through Interface) *(Đa kế thừa thông qua Interface)*:** A class inherits from multiple interfaces since Java does not support multiple inheritance using classes. *(Một lớp triển khai nhiều interface, vì Java không hỗ trợ đa kế thừa trực tiếp bằng `class`.)*
* **Hybrid Inheritance (through Interface) *(Kế thừa lai thông qua Interface)*:** A combination of two or more types of inheritance, achievable using interfaces. *(Sự kết hợp của hai hoặc nhiều loại kế thừa trên, thực hiện được nhờ sử dụng interface.)*

### 8. Polymorphism *(Tính đa hình)*
**Polymorphism** means **"many forms"**, where a single entity can behave differently in different situations. In Java, it allows the same method or object to show different behavior based on context.
*(**Tính đa hình** có nghĩa là **"nhiều hình thái"**, nơi một thực thể duy nhất có thể hành xử khác nhau trong các tình huống khác nhau. Trong Java, nó cho phép cùng một phương thức hoặc đối tượng thể hiện các hành vi khác nhau tùy theo ngữ cảnh.)*

* Same method, different behavior depending on the object. *(Cùng tên phương thức nhưng hành vi khác nhau tùy thuộc vào đối tượng thực thi.)*
* Achieved through **method overloading** and **method overriding**. *(Đạt được thông qua nạp chồng phương thức và ghi đè phương thức.)*

> **Example:** Different animals represent polymorphism, where the same method `speak()` produces different outputs like *Bark*, *Meow*, and *Moo* depending on the object.
> *(**Ví dụ:** Các loài động vật khác nhau thể hiện tính đa hình khi cùng gọi phương thức `speak()`, nhưng cho ra kết quả khác nhau như *Sủa*, *Meo meo*, và *Ò ó o* tùy theo từng loài.)*

#### Types of Polymorphism *(Các loại Đa hình trong Java)*:
* **Compile-time Polymorphism (Method Overloading) *(Đa hình lúc biên dịch - Nạp chồng phương thức)*:** Achieved when multiple methods have the same name but different parameters. The method call is resolved at compile time. *(Đạt được khi nhiều phương thức trong cùng một lớp có cùng tên nhưng khác danh sách tham số. Lời gọi hàm được xác định ngay tại thời điểm biên dịch.)*
* **Runtime Polymorphism (Method Overriding) *(Đa hình lúc chạy - Ghi đè phương thức)*:** Achieved when a subclass provides a specific implementation of a method already defined in its superclass. The method call is resolved at runtime based on the object. *(Đạt được khi lớp con cung cấp cách triển khai cụ thể cho một phương thức đã có sẵn ở lớp cha. Lời gọi hàm được quyết định lúc chương trình đang chạy dựa trên đối tượng thực tế.)*

## Advantage of OOP over Procedure-Oriented Programming Language
*(Ưu điểm của OOP so với Lập trình hướng thủ tục)*

* Code can be reused through classes, objects, inheritance, and methods. *(Tái sử dụng mã nguồn thông qua lớp, đối tượng, kế thừa và phương thức.)*
* Programs are easier to organize and maintain. *(Chương trình dễ tổ chức và bảo trì hơn.)*
* Large programs can be divided into smaller and manageable parts. *(Các chương trình lớn có thể chia nhỏ thành các phần dễ quản lý.)*
* Data can be protected using encapsulation. *(Dữ liệu được bảo vệ an toàn nhờ tính đóng gói.)*
* Changes in one part of the program have less impact on other parts. *(Thay đổi ở một phần ít gây ảnh hưởng đến các phần khác.)*
* Makes it easier to develop and maintain large applications. *(Giúp phát triển và duy trì các ứng dụng quy mô lớn dễ dàng hơn.)*
* Supports concepts like inheritance, polymorphism, and abstraction. *(Hỗ trợ các tính năng mạnh mẽ như kế thừa, đa hình và trừu tượng.)*

## Limitations of OOP *(Hạn chế của OOP)*

* **Steeper Learning Curve *(Khó tiếp cận hơn)*:** Concepts such as classes, objects, inheritance, polymorphism, abstraction, and encapsulation can be challenging for beginners. *(Các khái niệm như lớp, đối tượng, kế thừa, đa hình, trừu tượng và đóng gói có thể gây khó khăn cho người mới.)*
* **Additional Overhead for Small Programs *(Dư thừa cấu trúc với chương trình nhỏ)*:** OOP may introduce extra classes and structure that are unnecessary for simple applications. *(Tạo ra nhiều lớp và cấu trúc không cần thiết cho các ứng dụng đơn giản.)*
* **Increased Design Complexity *(Tăng độ phức tạp thiết kế)*:** Designing a proper class hierarchy and object relationships requires careful planning. *(Việc thiết kế hệ thống phân cấp lớp và quan hệ giữa các đối tượng đòi hỏi sự tính toán kỹ lưỡng.)*
* **Higher Memory Consumption *(Tiêu tốn bộ nhớ hơn)*:** Creating and managing a large number of objects can require more memory compared to procedural approaches. *(Khởi tạo và quản lý số lượng lớn đối tượng có thể tốn nhiều bộ nhớ hơn lập trình thủ tục.)*

## Suggested Quiz *(Câu hỏi ôn tập)*

**Question:** Which of the following correctly describes the relationship between interfaces and abstract classes in the context of inheritance?
*(Câu nào sau đây mô tả đúng mối quan hệ giữa `interface` và `abstract class` trong ngữ cảnh kế thừa?)*

* **A.** Abstract classes can implement interfaces and provide default method implementations. *(Lớp trừu tượng có thể triển khai các interface và cung cấp phần cài đặt mặc định cho phương thức.)*
* **B.** Interfaces can extend abstract classes. *(Interface có thể kế thừa từ lớp trừu tượng.)*
* **C.** Interfaces must be extended using the `extends` keyword only by other interfaces. *(Interface chỉ có thể được kế thừa bằng từ khóa `extends` bởi các interface khác.)*
* **D.** An abstract class can extend multiple interfaces directly. *(Một lớp trừu tượng có thể `extends` trực tiếp nhiều interface.)*

> **Đáp án đúng:** **A** *(Trong Java, một `abstract class` có thể dùng từ khóa `implements` để triển khai một hoặc nhiều `interface`, và nó có thể cài đặt sẵn các phương thức đó hoặc để lại cho lớp con kế thừa nó cài đặt sau).*
