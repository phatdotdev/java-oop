# Encapsulation in Java *(Tính đóng gói trong Java)*

**Last Updated:** 29 Aug, 2026 *(Cập nhật lần cuối: 29/08/2026)*

**Encapsulation** in Java is an object-oriented programming concept that bundles data and the methods that operate on that data into a single unit, such as a class. It also helps control access to the object's internal state by restricting direct access and providing controlled ways to read or modify it.

> **Giải thích:** **Tính đóng gói (Encapsulation)** trong Java là một khái niệm của lập trình hướng đối tượng nhằm gom nhóm dữ liệu (thuộc tính) và các phương thức thao tác trên dữ liệu đó vào chung một đơn vị duy nhất, chẳng hạn như một `class`. Nó cũng giúp kiểm soát quyền truy cập vào trạng thái bên trong của đối tượng bằng cách hạn chế truy cập trực tiếp và cung cấp các phương thức có kiểm soát để đọc hoặc chỉnh sửa dữ liệu.

* **Usually uses `private` fields to restrict direct access.** *(Thường sử dụng các thuộc tính `private` để hạn chế truy cập trực tiếp từ bên ngoài.)*
* **Provides controlled access through methods such as getters and setters when required.** *(Cung cấp quyền truy cập có kiểm soát thông qua các phương thức như `getter` và `setter` khi cần thiết.)*
* **Allows validation and other rules to be applied before changing data.** *(Cho phép áp dụng các quy tắc kiểm tra tính hợp lệ (validation) trước khi thay đổi dữ liệu.)*

---

## How Encapsulation is Achieved in Java *(Cách đạt được Tính đóng gói trong Java)*

Encapsulation is commonly implemented by *(Tính đóng gói thường được triển khai bằng cách)*:

* **Declaring fields as `private`.** *(Khai báo các biến thuộc tính là `private`.)*
* **Providing `public` or appropriately accessible methods to read or modify the fields.** *(Cung cấp các phương thức `public` hoặc có phạm vi truy cập phù hợp để đọc hoặc chỉnh sửa thuộc tính.)*
* **Adding validation inside methods when necessary.** *(Thêm logic kiểm tra tính hợp lệ bên trong các phương thức khi cần.)*
* **Keeping the internal implementation hidden from code outside the class.** *(Giữ kín phần cài đặt xử lý bên trong khỏi mã nguồn bên ngoài lớp.)*

### Rules *(Các quy tắc cốt lõi)*:

* **Declare data as `private` *(Khai báo dữ liệu là `private`)*:** Hide the class data so it cannot be accessed directly from outside the class. *(Ẩn dữ liệu của lớp để không thể bị truy xuất trực tiếp từ bên ngoài.)*
* **Use getters and setters *(Sử dụng getter và setter)*:** Keep variables `private` and provide `public` getter and setter methods for controlled access and safe modification, often with validation. *(Giữ biến ở trạng thái `private` và cung cấp các hàm `getter`, `setter` công khai để truy xuất có kiểm soát và chỉnh sửa an toàn, thường đi kèm kiểm tra điều kiện.)*
* **Apply proper access modifiers *(Áp dụng phạm vi truy cập phù hợp)*:** Use `private` for data hiding and `public` for methods that provide access. *(Dùng `private` để che giấu dữ liệu và `public` cho các phương thức cung cấp quyền giao tiếp.)*

---

## Code Example *(Ví dụ minh họa)*

```java
class Programmer {

    private String name;

    // Getter method used to get the data (Phương thức Getter dùng để lấy dữ liệu)
    public String getName() { 
        return name; 
    }

    // Setter method is used to set or modify the data (Phương thức Setter dùng để gán hoặc sửa dữ liệu)
    public void setName(String name) {
        this.name = name;
    }
}

public class Geeks {

    public static void main(String[] args) {
        Programmer p = new Programmer();
        p.setName("Geek");
        System.out.println("Name=> " + p.getName());
    }
}
```

**Output *(Kết quả)*:**
```text
Name=> Geek
```

**Explanation *(Giải thích)*:** In the above example, we use encapsulation and provide getter (`getName`) and setter (`setName`) methods which are used to show and modify the `private` data. This encapsulation mechanism protects the internal state of the `Programmer` object and allows for better control and flexibility in how the `name` attribute is accessed and modified.
*(Trong ví dụ trên, chúng ta áp dụng tính đóng gói và cung cấp các phương thức `getName` và `setName` để hiển thị và thay đổi dữ liệu `private`. Cơ chế đóng gói này bảo vệ trạng thái bên trong của đối tượng `Programmer`, đồng thời cho phép kiểm soát chặt chẽ và linh hoạt hơn cách thuộc tính `name` được truy cập và chỉnh sửa.)*

## Advantages of Encapsulation *(Ưu điểm của Tính đóng gói)*

* **Protects an object's internal data from direct access.** *(Bảo vệ dữ liệu bên trong đối tượng khỏi việc bị truy cập/thay đổi trực tiếp trái phép.)*
* **Allows validation before data is modified.** *(Cho phép kiểm tra tính hợp lệ trước khi dữ liệu bị thay đổi.)*
* **Makes code easier to maintain and modify.** *(Giúp mã nguồn dễ bảo trì và chỉnh sửa hơn.)*
* **Keeps related data and methods together in one class.** *(Gom giữ dữ liệu và các phương thức liên quan lại cùng một nơi trong một class.)*
* **Reduces dependency on the internal implementation of a class.** *(Giảm sự phụ thuộc của bên ngoài vào cách cài đặt chi tiết bên trong lớp.)*
* **Provides better control over how an object's state can be accessed or changed.** *(Kiểm soát tốt hơn cách trạng thái của đối tượng được đọc hoặc thay đổi.)*

---

## Limitations of Encapsulation *(Hạn chế của Tính đóng gói)*

* **Can increase the amount of code when many accessor methods are required.** *(Có thể làm tăng lượng mã nguồn khi phải viết quá nhiều phương thức getter/setter.)*
* **May add unnecessary complexity for very simple classes.** *(Có thể tạo ra sự phức tạp không cần thiết đối với các lớp quá đơn giản.)*
* **Requires careful design to decide which data and operations should be exposed.** *(Đòi hỏi thiết kế cẩn thận để quyết định dữ liệu và thao tác nào nên được công khai.)*
* **Excessive use of getters and setters can expose more of a class's internal state than necessary.** *(Việc lạm dụng getter và setter cho mọi thuộc tính có thể vô tình làm lộ trạng thái bên trong của lớp nhiều hơn mức cần thiết.)*

## Data Hiding vs Encapsulation *(So sánh Che giấu dữ liệu và Tính đóng gói)*

| Aspect *(Khía cạnh)* | Data Hiding *(Che giấu dữ liệu)* | Encapsulation *(Tính đóng gói)* |
| :--- | :--- | :--- |
| **Meaning** *(Ý nghĩa)* | Restricts direct access to internal data. *(Hạn chế quyền truy cập trực tiếp vào dữ liệu bên trong.)* | Bundles data and related methods into a class. *(Gom nhóm dữ liệu và các phương thức liên quan vào chung một lớp.)* |
| **Main focus** *(Trọng tâm chính)* | Controlling access to data. *(Kiểm soát quyền truy cập vào dữ liệu.)* | Organizing data and behavior together. *(Tổ chức dữ liệu và hành vi đi liền với nhau.)* |
| **Purpose** *(Mục đích)* | Protects internal state from unwanted direct access. *(Bảo vệ trạng thái nội bộ khỏi truy cập trực tiếp ngoài ý muốn.)* | Provides a controlled and well-defined interface. *(Cung cấp một giao diện giao tiếp rõ ràng và có kiểm soát.)* |
| **Commonly achieved using** *(Cách thực hiện)* | Access modifiers such as `private`. *(Các từ khóa phạm vi truy cập như `private`.)* | Classes, access control, and methods. *(Sử dụng Class, kiểm soát truy cập và các phương thức.)* |
| **Scope** *(Phạm vi)* | Mainly concerned with restricting access. *(Chủ yếu tập trung vào việc giới hạn quyền truy cập.)* | Broader concept that includes bundling and access control. *(Khái niệm rộng hơn, bao gồm cả việc đóng gói thành phần và kiểm soát truy cập.)* |
| **Example** *(Ví dụ)* | `private int balance;` | `class Account { private int balance; void deposit() {...} }` |
