# Polymorphism in Java *(Tính đa hình trong Java)*

**Last Updated:** 31 Aug, 2026 *(Cập nhật lần cuối: 31/08/2026)*

**Polymorphism** is one of the fundamental concepts of Object-Oriented Programming (OOP) that allows a single entity to take multiple forms. It enables the same method or interface to behave differently depending on the object involved. Polymorphism improves code flexibility, reusability, and maintainability.

> **Giải thích:** **Tính đa hình (Polymorphism)** là một trong những khái niệm nền tảng của Lập trình hướng đối tượng (OOP), cho phép một thực thể duy nhất có thể tồn tại dưới nhiều hình thái khác nhau. Nó cho phép cùng một phương thức hoặc giao diện thực hiện các hành vi khác nhau tùy thuộc vào đối tượng cụ thể đang gọi nó, giúp tăng tính linh hoạt, khả năng tái sử dụng và bảo trì mã nguồn.

* **Polymorphism means "many forms".** *(Đa hình có nghĩa là "nhiều hình thái".)*

* **It allows the same method to exhibit different behaviors.** *(Cho phép cùng một phương thức thể hiện nhiều hành vi khác nhau.)*

* **It is achieved through method overloading and method overriding.** *(Đạt được thông qua nạp chồng phương thức (method overloading) và ghi đè phương thức (method overriding).)*

> **Example:** Consider a person who plays different roles in life, like a father, a husband, and an employee. Each of these roles defines different behaviors of the person depending on the object calling it.
> *(**Ví dụ:** Hãy nghĩ về một người đàn ông đóng nhiều vai trò khác nhau trong cuộc sống như làm cha, làm chồng và làm nhân viên. Mỗi vai trò sẽ định nghĩa cách hành xử khác nhau của người đó tùy theo ngữ cảnh).*

### Basic Example *(Ví dụ cơ bản)*

```java
class Person {

    // Method that displays the role of a person
    // (Phương thức hiển thị vai trò của một người)
    void role() { 
        System.out.println("I am a person."); 
    }
}

// Derived class Father that overrides the role method
// (Lớp dẫn xuất Father ghi đè phương thức role)
class Father extends Person {

    // Overridden method to show the role of a father
    @Override 
    void role() {
        System.out.println("I am a father.");
    }
}

public class Main {
    public static void main(String[] args) {

        // Creating a reference of type Person but initializing it with Father class object
        // (Tạo biến tham chiếu kiểu Person nhưng khởi tạo bằng đối tượng thuộc lớp Father)
        Person p = new Father();

        // Calling the role method. It calls the overridden version in Father class
        p.role();
    }
}
```

**Output *(Kết quả)*:**

```text
I am a father.
```

**Explanation *(Giải thích)*:** In the above example, the `Person` class has a method `role()` that prints a general message. The `Father` class overrides `role()` to print a specific message. The reference of type `Person` is used to point to an object of type `Father`, demonstrating polymorphism at runtime. The overridden method in `Father` is invoked when `role()` is called.
*(Trong ví dụ trên, lớp `Person` có phương thức `role()` in ra thông báo chung. Lớp `Father` ghi đè `role()` để in ra thông báo cụ thể. Biến tham chiếu kiểu `Person` được dùng để trỏ tới đối tượng `Father`, minh họa tính đa hình lúc chạy (runtime). Khi gọi `p.role()`, phiên bản đã ghi đè trong lớp `Father` sẽ được thực thi).*

## Types of Polymorphism in Java *(Các loại Đa hình trong Java)*

In Java, Polymorphism is mainly divided into two types *(Trong Java, tính đa hình được chia làm 2 loại chính)*:

### 1. Compile-Time Polymorphism *(Đa hình lúc biên dịch)*

**Compile-time polymorphism**, also known as **static polymorphism**, occurs when the method to be executed is determined during compilation. It is primarily achieved through **method overloading**.
*(**Đa hình lúc biên dịch**, còn gọi là **đa hình tĩnh**, xảy ra khi phương thức nào sẽ được thực thi được trình biên dịch xác định ngay trong quá trình biên dịch code. Loại này đạt được chủ yếu thông qua **nạp chồng phương thức (method overloading)**).*

* **Method selection occurs at compile time.** *(Việc chọn phương thức diễn ra tại thời điểm biên dịch.)*

* **Improves readability and flexibility.** *(Cải thiện khả năng đọc hiểu và tính linh hoạt của mã nguồn.)*

#### Method Overloading *(Nạp chồng phương thức)*

Method overloading allows multiple methods with the **same name** but **different parameter lists** within the same class. The compiler chooses the appropriate method based on the arguments passed. The parameters can differ in:
*(Nạp chồng phương thức cho phép tạo nhiều phương thức **cùng tên** nhưng **khác danh sách tham số** bên trong cùng một lớp. Trình biên dịch sẽ chọn hàm phù hợp dựa trên đối số truyền vào. Tham số có thể khác nhau về:)*

* **Number of parameters** *(Số lượng tham số)*
* **Data types of parameters** *(Kiểu dữ liệu của tham số)*
* **Order of parameters** *(Thứ tự của các tham số)*

**Syntax *(Cú pháp)*:**

```java
class Demo {
    void show(int a) {
    }
    void show(int a, int b) {
    }
}
```

**Example: Method overloading by changing parameter types *(Ví dụ: Nạp chồng phương thức bằng cách thay đổi kiểu tham số)***

```java
class Helper {

    // Method 1: With 2 integer parameters
    // (Phương thức 1: Nhận 2 tham số kiểu int)
    static int Multiply(int a, int b) {
        return a * b;
    }

    // Method 2: With same name but with 2 double parameters
    // (Phương thức 2: Cùng tên nhưng nhận 2 tham số kiểu double)
    static double Multiply(double a, double b) {
        return a * b;
    }
}

// Main class
class Geeks {
    public static void main(String[] args) {
        // Calling method by passing different types of arguments
        System.out.println(Helper.Multiply(2, 4));
        System.out.println(Helper.Multiply(5.5, 6.3));
    }
}
```

**Output *(Kết quả)*:**

```text
8
34.65
```

**Explanation *(Giải thích)*:** The `Multiply` method is overloaded with different parameter types. The compiler picks the correct method during compile time based on the arguments. *(Phương thức `Multiply` được nạp chồng với các kiểu tham số khác nhau. Trình biên dịch sẽ chọn đúng hàm ngay lúc biên dịch dựa trên kiểu dữ liệu truyền vào).*

---

### 2. Runtime Polymorphism *(Đa hình lúc chạy)*

**Runtime polymorphism**, also known as **dynamic polymorphism**, occurs when the method call is resolved during program execution. It is achieved through **method overriding**.
*(**Đa hình lúc chạy**, còn gọi là **đa hình động**, xảy ra khi lời gọi phương thức chỉ được quyết định trong lúc chương trình đang chạy (thực thi). Loại này đạt được thông qua **ghi đè phương thức (method overriding)**).*

* **Method selection occurs at runtime.** *(Việc chọn phương thức diễn ra tại thời điểm chạy.)*

* **Depends on the actual object type.** *(Phụ thuộc vào kiểu đối tượng thực tế được khởi tạo trong bộ nhớ.)*

#### Method Overriding *(Ghi đè phương thức)*

Method overriding occurs when a subclass provides its own implementation of a method already defined in its superclass. The overridden method is selected based on the actual object created.
*(Ghi đè phương thức xảy ra khi lớp con cung cấp cách cài đặt riêng cho một phương thức đã được định nghĩa sẵn ở lớp cha. Phương thức được chọn phụ thuộc vào đối tượng thực tế được tạo ra).*

**Syntax *(Cú pháp)*:**

```java
class Parent {
    void print() {
    }
}

class Child extends Parent {
    @Override
    void print() {
    }
}
```

> **Note *(Lưu ý)*:** At runtime, the method that gets executed depends on the **actual object type**, not the reference type. *(Tại thời điểm chạy, phương thức được thực thi phụ thuộc vào **kiểu của đối tượng thực tế**, không phụ thuộc vào kiểu của biến tham chiếu).*

**Example *(Ví dụ)*:**

```java
// Class 1: Parent class (Lớp cha)
class Parent {
    void Print() { 
        System.out.println("parent class"); 
    }
}

// Class 2: Subclass 1 (Lớp con 1)
class Subclass1 extends Parent {
    @Override
    void Print() { 
        System.out.println("subclass1"); 
    }
}

// Class 3: Subclass 2 (Lớp con 2)
class Subclass2 extends Parent {
    @Override
    void Print() { 
        System.out.println("subclass2"); 
    }
}

// Class 4: Main class
class Geeks {
    public static void main(String[] args) {
        Parent a;

        a = new Subclass1();
        a.Print();

        a = new Subclass2();
        a.Print();
    }
}
```

**Output *(Kết quả)*:**

```text
subclass1
subclass2
```

**Explanation *(Giải thích)*:** When an object of a child class is created, the overridden method inside the child class is called. At runtime, the JVM determines which method to execute based on the actual type of the object, not the reference type. *(Khi tạo đối tượng của lớp con, phương thức đã ghi đè bên trong lớp con đó sẽ được gọi. Lúc chạy, máy ảo JVM tự động xác định hàm cần chạy dựa trên kiểu thực tế của đối tượng mà biến `a` đang trỏ tới).*

## Compile-Time vs Runtime Polymorphism *(So sánh Đa hình lúc biên dịch và Đa hình lúc chạy)*

| Feature *(Tiêu chí)* | Compile-Time Polymorphism *(Đa hình lúc biên dịch)* | Runtime Polymorphism *(Đa hình lúc chạy)* |
| :--- | :--- | :--- |
| **Also called** *(Tên gọi khác)* | Static polymorphism *(Đa hình tĩnh)* | Dynamic polymorphism *(Đa hình động)* |
| **Mainly achieved using** *(Cách thực hiện)* | Method overloading *(Nạp chồng phương thức)* | Method overriding *(Ghi đè phương thức)* |
| **Method selection** *(Thời điểm chọn hàm)* | Compile time *(Lúc biên dịch)* | Runtime *(Lúc chạy chương trình)* |
| **Inheritance required** *(Yêu cầu kế thừa)* | No *(Không bắt buộc)* | Yes *(Bắt buộc)* |
| **Example** *(Ví dụ)* | `add(int, int)` and `add(double, double)` | `Dog.sound()` overriding `Animal.sound()` |

## Advantages of Polymorphism *(Ưu điểm của Tính đa hình)*

* **Makes code flexible and reusable.** *(Giúp mã nguồn linh hoạt và dễ tái sử dụng.)*

* **Improves code readability.** *(Cải thiện tính rõ ràng, dễ đọc của chương trình.)*

* **Makes programs easier to maintain.** *(Giúp chương trình dễ bảo trì hơn.)*

* **Allows the same method to perform different tasks.** *(Cho phép cùng một tên phương thức thực hiện nhiều nhiệm vụ khác nhau.)*

* **Makes it easier to add new classes and features.** *(Dễ dàng mở rộng thêm các lớp con và tính năng mới mà không làm hỏng code cũ.)*

* **Supports abstraction and loose coupling.** *(Hỗ trợ tính trừu tượng và giảm sự phụ thuộc chặt chẽ giữa các thành phần.)*

## Disadvantages of Polymorphism *(Nhược điểm của Tính đa hình)*

* **Can make code more complex to understand.** *(Có thể làm luồng chạy của code trở nên phức tạp hơn đối với người mới.)*

* **Can make debugging difficult, especially with runtime polymorphism.** *(Gây khó khăn hơn khi gỡ lỗi (debug), đặc biệt là với đa hình lúc chạy vì phải xác định đúng đối tượng thực tế lúc runtime.)*

* **May require more classes and methods, increasing code size.** *(Có thể cần tạo nhiều lớp và phương thức hơn, làm tăng dung lượng mã nguồn.)*

* **Runtime polymorphism can have a small performance overhead.** *(Đa hình lúc chạy có thể tốn thêm một chút chi phí hiệu năng do cơ chế tra cứu phương thức động - dynamic method dispatch).*

* **Improper use can make the program harder to maintain.** *(Nếu lạm dụng hoặc thiết kế sai cây kế thừa sẽ làm chương trình khó bảo trì.)*

## Suggested Quiz *(Câu hỏi ôn tập)*

**Question:** What is the key difference between compile-time and runtime polymorphism in Java?
*(Sự khác biệt cốt lõi giữa đa hình lúc biên dịch và đa hình lúc chạy trong Java là gì?)*

* **A.** Compile-time polymorphism is implemented using method overriding, while runtime polymorphism is implemented using method overloading. *(Đa hình lúc biên dịch dùng overriding, còn đa hình lúc chạy dùng overloading.)*
* **B.** Runtime polymorphism is faster than compile-time polymorphism. *(Đa hình lúc chạy nhanh hơn đa hình lúc biên dịch.)*
* **C.** Compile-time polymorphism is determined during compilation, while runtime polymorphism is resolved at runtime. *(Đa hình lúc biên dịch được xác định trong quá trình biên dịch, còn đa hình lúc chạy được phân giải tại thời điểm chạy.)*
* **D.** Compile-time polymorphism is achieved using interfaces. *(Đa hình lúc biên dịch đạt được thông qua interface.)*

> **Đáp án đúng:** **C** *(Đa hình lúc biên dịch - overloading được trình biên dịch quyết định ngay khi compile dựa vào tham số; còn đa hình lúc chạy - overriding được JVM quyết định lúc runtime dựa trên đối tượng thực tế).*
